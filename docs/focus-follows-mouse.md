# Focus follows mouse

Add an opt-in **Focus follows mouse** preference. When enabled, resting the pointer over a visible window managed by Mosaico gives that window keyboard focus and raises it. Expose the same preference in the Mosaico menu bar menu and under **Settings → General → Mouse**. Both controls take effect immediately and persist across launches.

## Prior art

- yabai defaults to `off` and offers `autofocus` (focus without raising) and `autoraise` (focus and raise). Holding its mouse modifier suspends hover focus so the user can reach the menu bar. Mosaico’s existing focus operation already activates and raises the target, so the first release can use that path. A focus-only mode would need separate validation of activation and stacking across apps. [yabai configuration](https://github.com/asmvik/yabai/wiki/Configuration/72f492eb2d6f1bc5cdba4f959add25450babca1e)
- AeroSpace introduced `focus-follows-mouse` in v0.21.0 Beta and ships it disabled. Its next release fixed hover through system menu dropdowns and a fullscreen case. A later report identifies a separate native macOS fullscreen case. Include both menus and native fullscreen in the release checks. [AeroSpace releases](https://github.com/nikitabobko/AeroSpace/releases) · [Default configuration](https://github.com/nikitabobko/AeroSpace/blob/main/docs/config-examples/default-config.toml) · [Native fullscreen report](https://github.com/nikitabobko/AeroSpace/discussions/2277)

## Interaction

- Start with a fixed **150 ms dwell** over the same eligible window. It can continue while the pointer moves within that window. Crossing into another window, a gap, or blocked UI clears or replaces the candidate. The timing is a starting point to verify in the packaged app.
- Include managed tiled and floating windows on visible regular desktops, including on a second display. Use the topmost surface at the pointer. An excluded window, dialog, or overlay above a managed window blocks the underlying window. Leave focus where it is over gaps, desktop, Dock, and menu bar UI.
- Suspend hover focus while a mouse button is held, during native or Mosaico drags, while Option is held, during menu tracking and while Mosaico Settings is key. Option is Mosaico’s existing drag modifier and doubles as a way to pass over windows on the way to an app’s menu. Also suspend during Mission Control, native fullscreen on the pointer’s display, and Space, display, and wake transitions. Cancel pending work on suspension and require fresh pointer motion to rearm it.
- A click or explicit focus command wins over pending hover work. After a keyboard focus change, if the pointer stays over its old window, moving within that same window keeps keyboard focus. Leaving and re-entering it starts a new dwell. Turning the setting on or resuming Mosaico also requires fresh motion.
- Keep **Pointer follows the focused window** independent. Hover-driven focus leaves the pointer in place, even when both options are on. Explicit keyboard commands continue to use the existing pointer-warp behavior.

## Implementation

1. **Preference and controls.** Add `focusFollowsMouse` to [`MosaicoSettings`](../Sources/Mosaico/Settings/SettingsStore.swift) with a `false` default and a missing-key decoding fallback. Bind a checked item in [`MenuContent`](../Sources/Mosaico/App/MenuContent.swift) and a toggle in [`SettingsView`](../Sources/Mosaico/Settings/SettingsView.swift) to `SettingsStore.shared`. Use the existing `.menu` checkmark pattern if a SwiftUI `Toggle` renders poorly there. Add the English source key and its Italian translation to [`Localizable.strings`](../Resources/it.lproj/Localizable.strings). The checkmark reflects the saved preference while Mosaico is paused. Route hover-only setting changes around the existing hotkey re-registration and retiling path.
2. **Passive motion and lifecycle.** Prototype an AppKit global `.mouseMoved` monitor. [`MouseManager`](../Sources/Mosaico/Mouse/MouseManager.swift) deliberately omitted motion from its modifying event tap after cursor flicker. Keep the modifying tap’s event mask intact. Coalesce movement to the latest Quartz-coordinate point and bound hit-test frequency, with a single scheduled dwell and a final check at expiry. Keep the input callback free of AX and window-list queries. Install the observer only while the manager is started, enabled, and unpaused. Remove it and cancel queued work on disable, pause, or stop. Reuse existing lifecycle hooks to invalidate pending work during transitions. Use the existing synthetic drag event tag wherever a `CGEvent` is available, plus explicit suspension during native Space moves. Cancel and rebase hover tracking around the app’s own pointer warps.
3. **Hit testing and eligibility.** Add a hover-specific query in [`WindowDiscovery`](../Sources/Mosaico/Core/WindowDiscovery.swift). Core Graphics returns `.optionOnScreenOnly` windows front to back. The existing `frontWindow(at:)` only considers layer 0 and can miss menu, Dock, and panel blockers. Preserve those blockers in the hover query, and identify the first relevant surface before checking whether it is managed. Prototype which system surfaces need explicit detection and how to handle transparent or ambiguous hits. Skip uncertain hits. Revalidate the window ID, owner PID, pointer position, and current regular desktop at dwell expiry using [`WorkspaceManager`](../Sources/Mosaico/Workspaces/WorkspaceManager.swift) and [`SpaceTracker`](../Sources/Mosaico/Displays/SpaceTracker.swift). The drag cache uses layout geometry and the reconciliation snapshot sorts by ID, so use a fresh stacking-order hit for the final decision. [Apple’s on-screen window list documentation](https://developer.apple.com/documentation/coregraphics/cgwindowlistoption/optiononscreenonly)
4. **Focus and feedback.** Let [`WindowManager`](../Sources/Mosaico/Core/WindowManager.swift) arbitrate hover requests and dispatch the existing [`AXWindow.focus()`](../Sources/Mosaico/Core/AXWindow.swift) operation. Skip requests for the actual focused window. Track the hover request by target ID and PID with bounded expiry so both app activation and AX focus notifications can confirm it without causing a passive pointer warp. Update focus history on confirmed focus and clear the request on failure, supersession, or timeout. Avoid repeatedly calling AX while the pointer remains over a failed target.

## Verification

- Add deterministic checks to [`SelfTest.swift`](../Sources/Mosaico/SelfTest.swift) for legacy settings decoding, preference round trips, topmost-window selection with blockers, dwell cancellation, keyboard rearm behavior, and warp suppression. Drive hover decisions with controlled time and hit-test inputs. Run `swift build` and `.build/debug/Mosaico --selftest`.
- In the packaged app, exercise both toggles, persistence, pause and resume, and all four combinations of the two mouse preferences. Verify typing goes to the hovered window across same-app windows, different apps, tiled and overlapping floating windows, and two displays. Verify rapid pointer crossings, commands during dwell, and an obscured or excluded window.
- Verify app and status menus, Dock, dialogs, Settings, text selection, modifier drag and resize, native Space moves, Mission Control, fullscreen and zoom, and display reconnect. Check I-beam, resize, and link cursors for flicker and confirm that hover still works after suspend and resume. Test the passive observer with the app’s existing permissions on the oldest supported and a current macOS release before deciding whether any permission handling is needed.
